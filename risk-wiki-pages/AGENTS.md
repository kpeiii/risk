# 投資風險衡量 Wiki — Agent 工作規範

本專案是依 Karpathy「LLM Wiki」模式建立的個人知識庫:你(Agent)負責撰寫與維護整個 wiki,使用者負責挑選論文、參與討論與提問。知識在 ingest 時被編譯進 wiki 並持續更新,而不是每次提問時重新從 PDF 推導。

## 1. 目標與範圍

- **領域**:投資風險衡量的學術論文。
- **核心用途**:比較各種風險指標(VaR、CVaR/Expected Shortfall、Sharpe ratio、maximum drawdown 等)的**假設、優缺點與適用情境**。
- **第一版範圍**:只處理風險指標。
- **預留擴充(尚未啟用)**:「交易心法」(行為偏誤、交易紀律等)。使用者決定整理方向之前,**不要**建立相關資料夾或頁面。若 ingest 的論文明顯屬於此範疇,請告知使用者並暫不寫入。

## 2. 三層架構

| 層 | 位置 | 誰寫 | 規則 |
|---|---|---|---|
| 原始來源 | `raw/` | 使用者 | PDF 論文。**絕對不可修改、移動、刪除或重新命名。** |
| Wiki | `wiki/` | Agent | 全部由你撰寫與維護。使用者只閱讀,偶爾要求修正。 |
| Schema | 本檔 `AGENTS.md` | 雙方共同演進 | 工作流程有改動時,與使用者討論後更新本檔。 |

`CLAUDE.md` 只引用本檔,不要在裡面加內容。

## 3. 目錄結構

```
raw/                 PDF 論文(唯讀)
wiki/
├── index.md         內容目錄(每次 ingest 都要更新)
├── log.md           時間序操作紀錄(只增不改)
├── overview.md      整體綜述:目前對各風險指標的整體理解
├── sources/         每篇論文一頁摘要
├── metrics/         每個風險指標一頁
├── concepts/        支撐概念(如常態假設、肥尾、一致性風險度量)
└── comparisons/     指標之間的比較與綜合分析
```

### 檔名規則
- 一律使用小寫英文與連字號(kebab-case),例如 `value-at-risk.md`、`expected-shortfall.md`。
- 論文頁:`作者姓氏-年份-關鍵字.md`,例如 `artzner-1999-coherent-measures.md`。多位作者只取第一作者姓氏。
- 比較頁:`a-vs-b.md` 或 `topic-comparison.md`。

## 4. 撰寫規範

### 語言
- 全部使用**繁體中文**。
- 專有名詞**第一次出現時**附英文原文,格式:風險值(Value at Risk, VaR)。同一頁之後可只用中文或縮寫。
- 論文標題、作者名一律保留英文原文。

### 連結
- 使用**標準 markdown 相對連結**,例如 `[風險值](../metrics/value-at-risk.md)`。
- **不要使用** `[[wikilink]]`。
- 提到已有頁面的指標或概念時,一律加上連結。

### 出處標註
- 標到**論文層級**即可:作者、年份、標題。格式:`(Artzner et al., 1999)`,並連結到 `sources/` 中對應的論文頁。
- 不需要標頁碼或章節。
- **不得憑記憶補充論文沒有說的內容。** 若必須加入背景知識(例如教科書上的標準定義)以便理解,須明確標註:`〔背景知識,非來自已 ingest 論文〕`。
- 無法確定某個數字或結論是否正確時,寫明「待核對」,不要猜測。

### 公式
- 每個指標頁都要有:**公式 + 白話解釋 + 簡單數值範例**。
- 公式使用 LaTeX(`$...$` 與 `$$...$$`)。
- 數值範例要簡單、可手算,並說明每個數字的來源。若範例是你自行設計而非論文所載,標註「說明用範例」。
- 讀 PDF 時若公式、符號或表格抽取不清楚,標註 `〔待人工核對〕`,並告知使用者,**不要自行補全**。

### Frontmatter
所有 wiki 頁面(`index.md`、`log.md` 除外)開頭加上 YAML frontmatter。

論文頁:
```yaml
---
type: source
title: 論文原文標題
authors: [Artzner, Delbaen, Eber, Heath]
year: 1999
raw_file: raw/檔名.pdf        # 若 PDF 尚未放入 raw/,寫 none
source_url: https://...       # 實際讀取的網址(raw_file 為 none 時必填)
access: full-text             # full-text | abstract-only
version_read: 預印本 1998-07-22 # 實際讀到的版本;與正式發表版可能不同
ingested: 2026-01-01
metrics: [value-at-risk, expected-shortfall]
---
```

`access: abstract-only` 的論文,其頁面內的結論僅限於摘要與二手資料所能支持的範圍,細節一律標 `〔待核對〕`。

指標頁:
```yaml
---
type: metric
name_zh: 風險值
name_en: Value at Risk
abbr: VaR
updated: 2026-01-01
source_count: 3
---
```

概念頁與比較頁:`type: concept` / `type: comparison`,並包含 `updated` 與 `source_count`。

## 5. 頁面模板

### 指標頁(`metrics/`)固定章節,依序如下
1. **定義** — 一至兩句話
2. **公式** — LaTeX
3. **白話解釋**
4. **數值範例**
5. **核心假設** — 條列;每項假設盡量連到對應的概念頁
6. **優點**
7. **缺點與限制**
8. **適用情境** — 什麼時候適合用、什麼時候不適合
9. **相關論文** — 列出並連結 `sources/` 頁面,各附一句話說明該論文對此指標的貢獻
10. **爭議與不確定性** — 見第 6 節

沒有資料的章節保留標題並寫「尚無已 ingest 論文涵蓋」,不要刪除章節。

### 論文頁(`sources/`)章節
1. **基本資料** — 作者、年份、期刊/來源
2. **研究問題**
3. **方法與資料** — 使用的模型、樣本期間、資料集、市場
4. **核心結論**
5. **涉及的風險指標** — 連結到 `metrics/`
6. **限制與注意事項**
7. **與其他論文的關係** — 支持、補充或矛盾,並連結

### 比較頁(`comparisons/`)
- 以表格呈現指標在「假設、優點、缺點、適用情境」上的差異。
- 表格之後以文字說明如何選擇,並附出處。

## 6. 論文結論矛盾時的處理

不同論文結論衝突時,**不要刪除任何一方的主張**。在相關頁面的「爭議與不確定性」章節記錄:

1. **各方主張** — 附論文出處
2. **判斷依據** — 比較年份、資料(市場、樣本期間)、方法與假設的差異
3. **建議立場** — 你的判斷,以及為什麼
4. **信心程度** — 高 / 中 / 低,並說明不確定在哪裡

建議立場只是你的判斷,必須與論文主張分開寫清楚,不可混為一談。重大矛盾也要在 `overview.md` 中提及。

## 7. 操作流程

### Ingest(處理新論文)— 逐篇、先討論再寫入

使用者放入 PDF 並要求處理時:

1. **讀取** `raw/` 中指定的 PDF。以文字抽取為主;不清楚的公式、圖表標 `〔待人工核對〕`。
2. **先查現有 wiki**:讀 `wiki/index.md`,找出已有的相關頁面。**優先擴充既有頁面,避免建立近似重複的頁面。**
3. **向使用者報告並討論,此時還不寫入任何檔案**:
   - 論文的研究問題與核心結論
   - 方法與資料
   - 涉及哪些風險指標與概念
   - 與現有 wiki 內容相符或矛盾之處
   - 打算新增與更新的頁面清單
   - 你不確定或抽取不清楚的地方
4. **等待使用者確認或調整。** 使用者同意之前,不得寫入 wiki。
   - 例外:使用者明確授權批次處理(例如「直接幫我做」)時,可跳過討論直接寫入,但完成後必須在回報中列出各論文的重點、不確定之處與待核對項目,並在 `log.md` 備註「批次授權」。
5. **寫入**(一篇論文通常會動到多個頁面):
   - 建立 `sources/` 論文頁
   - 更新或建立相關 `metrics/`、`concepts/` 頁面
   - 必要時更新 `comparisons/` 與 `overview.md`
   - 更新各頁 frontmatter 的 `updated` 與 `source_count`
   - 更新 `index.md`
   - 在 `log.md` 追加一筆紀錄
6. **回報**實際變更了哪些檔案。

重寫摘要而非附加:當新論文改變了對某指標的整體理解,請**改寫**該頁相關段落,不要只在底部追加。

### Query(回答問題)

1. 先讀 `wiki/index.md`,找出相關頁面,再讀取那些頁面。
2. 根據 wiki 內容回答,附出處(論文層級)。
3. wiki 沒有涵蓋的內容,直接說明「目前 wiki 中沒有」,不要用記憶補答;若需要補充背景知識,依第 4 節標註。
4. 若回答是有價值的比較或分析,詢問使用者是否存回 `comparisons/`。
5. 在 `log.md` 記錄這次查詢(一行即可)。

### Lint(健康檢查)

使用者要求時執行,檢查:
- 頁面之間的矛盾,以及是否已記錄在「爭議與不確定性」
- 被新論文取代或已過時的主張
- 沒有任何連入連結的孤立頁面
- 被多處提及卻沒有獨立頁面的概念或指標
- 缺少交叉連結之處
- frontmatter 欄位缺漏或 `source_count` 與實際不符
- 標有 `〔待人工核對〕` 的項目清單
- 資料缺口,以及值得閱讀的新論文方向

**輸出檢查報告,修正前先詢問使用者。** 完成後在 `log.md` 記錄。

## 8. index.md 與 log.md 格式

### index.md
依類別分區(論文、指標、概念、比較),每項一行:

```
- [風險值(VaR)](metrics/value-at-risk.md) — 在給定信賴水準下的最大預期損失|3 篇論文
```

論文項目另附年份。每次 ingest 都要更新。

### log.md
只增不改,最新的在最下面。每筆以固定前綴開頭,方便用 `grep "^## \[" wiki/log.md | tail -5` 查看:

```
## [2026-01-01] ingest | Artzner et al. 1999 — Coherent Measures of Risk
- 新增:sources/artzner-1999-coherent-measures.md
- 更新:metrics/value-at-risk.md、concepts/coherent-risk-measure.md
- 備註:VaR 不滿足次可加性,已記錄於爭議與不確定性

## [2026-01-02] query | VaR 與 CVaR 在肥尾分布下的差異
## [2026-01-03] lint | 發現 2 個孤立頁面
```

操作類型只有:`ingest`、`query`、`lint`、`schema`(修改本檔時使用)。

## 9. 通則

- 不確定時,問使用者,不要猜。
- 每次動手前,先確認 `raw/` 以外的檔案才是你要寫入的對象。
- 保持頁面簡潔:寫重點,不要複製論文大段內容。
- 若你發現本檔的規則不夠用或互相衝突,停下來告知使用者,討論後再更新本檔。
